# Migrate an existing Claude-based installation

The artifact chain and human gates stay the same. The portable source of truth replaces
vendor-specific policy ownership; Claude remains available as a compatibility adapter.

| Previous source | Canonical source / boundary |
|-----------------|-----------------------------|
| CLAUDE.md project instructions | AGENTS.md; generated CLAUDE.md imports it |
| .claude/skills | .agents/skills; Claude discovery copies generated by sync-adapters |
| .claude/commands | .agents/commands; usable as plain task procedures by any agent |
| .claude/agents | .agents/roles; harness-native delegation remains optional |
| .claude/hooks policy logic | .agents/hooks + scripts/policy.py; scripts/claude_hook.py translates native events |
| .claude session markers/logs | .agents markers/logs; old markers recognized by the Claude bridge |
| Direct claude calls in CI/evals/monitoring | scripts/agent_run.py + explicit SDLC_AGENT_ADAPTER |
| Claude-native eval allowed_tools/max_turns | portable mode/timeout_seconds |
| Anthropic image entry point | provider-neutral runtime; native CLI install is opt-in and versioned |

On a customized copy, first preserve your existing CLAUDE.md, skills, commands, roles and
hook changes on a branch. Port that content into AGENTS.md and .agents before generating
adapters. Do not run generation over unsaved custom Claude files. Review the diff, run
`make sync-adapters`, `make template-check`, and representative live evals for each configured
adapter. Keep provider-specific permissions and managed settings at the adapter boundary;
managed-settings/ is explicitly a Claude example, not a portable enforcement mechanism.

Set SDLC_AGENT_ADAPTER=claude to retain the CLI integration and configure an exact CLI version.
Enable SDLC_CLAUDE_ACTION_ENABLED only if you want the optional @claude action workflows;
otherwise the shared agent-review workflow handles review. Both examples evals stay disabled
until replaced; zero cases is SKIPPED, and --require-enabled fails.

Credentialed evals run only on a schedule or a maintainer's manual workflow dispatch, with an
optional approved ref. Never treat a skipped PR eval job as evaluation evidence. PRs still
run offline adapter/policy tests in Template check. Required human G5 review should inspect
the corresponding completed eval run for the exact candidate commit before approving.

Hooks remain supplemental; review, branch protection and protected CI deployment environments
are required regardless of harness. Production credentials must not be available to ordinary
agent sessions. Custom adapters need explicit permission enforcement, result normalization
and their own contract/live tests; unsupported capabilities must fail, not be silently widened.
